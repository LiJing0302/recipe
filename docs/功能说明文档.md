## 1. 项目概览

**食光 AI** 是一款以「AI 助力家庭烹饪」为核心的食谱管理应用，覆盖**从买菜、备菜、做饭到社交分享**的完整家庭烹饪链路：

- **吃之前**：规划今日菜单、把食谱加入菜篮子、管理家中食材库存
- **做饭时**：分步烹饪模式 + AI 烹饪助手实时答疑 + 完成记录
- **做之后**：上传/分享食谱、广场浏览他人作品、关注作者、客人点单

支持 **H5 与微信小程序**双端运行（uni-app 跨端框架），前后端分离架构。

### 技术栈

| 层次 | 技术选型 |
|------|----------|
| 前端框架 | uni-app 3（Vue 3 + TypeScript） |
| 前端 UI | uview-plus 组件库 + 自定义组件，Pinia 状态管理 |
| 后端框架 | NestJS 11（Fastify 驱动） |
| 数据库 | PostgreSQL 16 + Prisma ORM（8 次迁移） |
| 对象存储 | MinIO / AWS S3 兼容存储（图片上传与代理） |
| 认证方式 | 账号密码 + JWT（Bearer Token） |

## 3. 核心功能详解

### 3.1 今日菜单（Menu）
- 按 `yyyy-MM-dd` 组织每日菜单，支持早/午/晚三餐（`breakfast / lunch / dinner`）
- 从食谱库添加菜品到指定日期与餐次，可附带点单人备注
- 客人点单（order）：记录点单人姓名与备注，自动生成当日晚餐菜单项
- 日期条组件（DateStrip）支持快速切换日期

### 3.2 菜篮子（Basket）
- 从任意食谱「一键加入菜篮」，自动展开该食谱全部食材作为待购项
- 已存在相同食材时去重、合并数量
- 支持手动添加/删除条目，一键将菜篮食材批量入库（生成食材库存批次）

### 3.3 食材库（Inventory）
- 按用户维度存储食材批次：名称、分类、数量、单位、购买日期、价格
- 来源类型（sourceType）：`recipe`（由食谱/菜篮生成）、`manual`（手动录入）
- 库存按批次管理，支持增删，适配「食材会过期」的真实场景

### 3.4 食谱管理（Recipes）
- **完整 CRUD**：新建、编辑、删除、查看食谱；支持公开/私有切换（isPublic）
- 食谱字段：标题、副标题、封面图、标签、口味、份量、烹饪时长、难度、评分、食材清单（JSON）、步骤（JSON，含分步图）
- **分类体系**：系统内置默认分类 + 用户自定义分类（名称、排序、删除），按用户隔离
- **分享**：生成不透明短分享 ID（shareId，服务端加密存储），他人无需登录即可通过分享链接浏览你的食谱

### 3.5 广场与社交（Community）
- 公开食谱流：分页加载（page/pageSize），支持按标签（tag）筛选
- 关注/取关作者（关注关系本地存储）
- 食谱卡片展示：封面、标题、作者、难度、评分、收藏数

### 3.6 AI 能力（当前为 Mock 实现）
AI 服务层（`src/services/ai.ts`）已抽象统一接口，现阶段返回模拟数据，未来可无缝接入真实模型：

| AI 能力 | 输入 | 输出 |
|---------|------|------|
| 食材识别 | 图片 URL | 识别出的食材列表（名称/预估量/置信度） |
| 食谱推荐 | 手头食材列表 | 推荐食谱 + 匹配度评分 + 缺少食材提示 |
| 烹饪助手 | 当前步骤 + 用户消息 | 下一步指引、火候建议、进度记录（自然语言对话） |

### 3.7 烹饪模式（Cooking）
- 步骤化引导：StepChecklist 组件逐项打勾，记录完成进度
- 分步图片展示，辅助判断火候与成品状态
- 完成后生成烹饪记录（CookingRecord），累计到用户烹饪统计

## 4. 数据模型（Prisma / PostgreSQL）

| 表 | 关键字段 | 说明 |
|----|----------|------|
| **User** | account（唯一）、passwordHash、name、avatar、bio、cookingDays、totalCooking、favoriteCount | 用户账号与统计 |
| **Recipe** | title、subtitle、cover、source、authorId、categories[]、tags[]、flavor、servings、duration、difficulty、rating、ingredients(JSON)、steps(JSON)、isPublic | 食谱主体；JSON 列存储食材与步骤 |
| **RecipeCategory** | name、position、isDefault、userId（唯一约束 userId+name） | 用户食谱分类 |
| **RecipeShareLink** | codeHash（唯一）、codeCiphertext、userId（唯一） | 分享短码（哈希存储） |

索引：Recipe 按 `authorId+createdAt`、`isPublic+createdAt` 建立索引，支撑「我的食谱」与「广场」两个高频列表查询。

## 6. 运行与部署

### 本地开发（三件套）
```bash
# 1. 数据库（PostgreSQL 16）
cd backend && docker compose up -d

# 2. 后端（NestJS，热重载）
cd backend && npm run start:dev   # → http://localhost:3000

# 3. 前端 H5（uni-app）
npm run dev:h5                    # → http://localhost:5173
# 微信小程序：npm run dev:mp-weixin，用微信开发者工具导入 dist/dev/mp-weixin
```

### 关键环境变量（backend/.env）
| 变量 | 说明 |
|------|------|
| DATABASE_URL | PostgreSQL 连接串（默认指向 localhost:5432/recipe_ai） |
| PORT | API 端口（默认 3000） |
| MinIO/S3 系列 | 对象存储配置（bucket 保持私有，图片经 /api/uploads/object 代理） |

### 生产构建
- 前端：`npm run build:h5` / `npm run build:mp-weixin`
- 后端：`cd backend && npm run build && node dist/main.js`
